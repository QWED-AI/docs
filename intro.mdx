## What is QWED?

QWED (Query With Evidence & Determinism) is a trust boundary for AI systems:

- LLMs can translate user intent into structured claims.
- QWED verifies those claims with deterministic engines before execution or response.
- You get proof-backed outcomes instead of probability-only confidence.

QWED is designed for LLM verification, AI agent security, verified tool calls, prompt injection defense, and deterministic transaction verification in high-stakes workflows.

> **"Do not trust generated output. Verify it."**

```mermaid

    U[User Query] --> L[LLM Translation]
    L --> Q[QWED Verification]
    Q --> R[Verified Result]

    L -. Untrusted output .-> X[Possible hallucination]

    class Q,Y trusted;
    class R result;
```

## Quick start (5 minutes)

```bash
pip install qwed==10.0.0
```

The examples below use the `qwed` CLI that this installs. The `qwedai/qwed-verification:10.0.0` Docker image runs the API server instead; see [Self-hosting](/advanced/self-hosting#docker).

```bash
# Run every engine on known cases (no LLM needed)
qwed test
# Math:
#   [ok] 2+2=4                  -> VERIFIED | ADMIT
#   [ok] 2+2=5                  -> VERIFIED (false) | DENY
#   ...

# Verify logic constraints
qwed verify-logic "(AND (GT x 5) (LT y 10))"
# -> SAT: {x=6, y=9}
```

## What's new in v10

<AccordionGroup>
  <Accordion title="Verdicts that prove the claim" icon="shield-check" defaultOpen>
    From v10.0.0, routes whose evidence doesn't prove the claim stop reporting `VERIFIED`. `/verify/rag` and `/verify/process` are `UNVERIFIABLE`, a consensus needs two distinct engines, an image size claim is decided only when it plainly states the dimensions, `/verify/math` without `=` is `UNVERIFIABLE`, and `/verify/logic` returns an admission, which is `BLOCKED`. The attestation, the audit log and the batch summary call a result verified only when it is `VERIFIED`, its claim holds, and it wasn't reached on a model's translation of the question. [Read the 10.0.0 notes →](/changelog#v10-0-0-—-verdicts-that-prove-the-claim-and-claude_opus-removed)
  </Accordion>
  <Accordion title="Before you upgrade" icon="triangle-exclamation">
    A client that acted on `status == "VERIFIED"` from these routes now sees `UNVERIFIABLE` or `BLOCKED`. `ACTIVE_PROVIDER=claude_opus` is refused: use `anthropic` and move the `CLAUDE_OPUS_*` settings to `ANTHROPIC_*`. The LangChain and CrewAI tools word undecided results differently, and the Go module path moves to `/v10`. [Read the upgrade steps →](/changelog#v10-0-0-—-verdicts-that-prove-the-claim-and-claude_opus-removed)
  </Accordion>
</AccordionGroup>
