<Note>
**QWED v10.0.0 is the current release.** Routes stop reporting `VERIFIED`, or admitting a result, on evidence that does not prove the claim: RAG and process checks are `UNVERIFIABLE`, a consensus needs two distinct engines, a logic verdict is not admitted, and `/verify/math` without `=` is `UNVERIFIABLE`. The `claude_opus` provider is removed, and the Go module path ends in `/v10`. Read the [10.0.0 upgrade steps](/changelog#v10-0-0-evidence-is-not-proof) before you upgrade.
</Note>

## What is QWED?

QWED (Query With Evidence & Determinism) is a trust boundary for AI systems:

- LLMs can translate user intent into structured claims.
- QWED verifies those claims with deterministic engines before execution or response.
- You get proof-backed outcomes instead of probability-only confidence.

QWED is designed for LLM verification, AI agent security, verified tool calls, prompt injection defense, and deterministic transaction verification in high-stakes workflows.

> **"Do not trust generated output. Verify it."**

```mermaid

    U[User Query] --> L[LLM Translation]
    L --> Q[QWED Verification]
    Q --> R[Verified Result]

    L -. Untrusted output .-> X[Possible hallucination]
    Q -. Deterministic proof .-> Y[Accepted or rejected]

    class Q,Y trusted;
    class R result;
```

## Quick start (5 minutes)

```bash
pip install qwed==10.0.0
```

The examples below use the `qwed` CLI that this installs. The `qwedai/qwed-verification:10.0.0` Docker image runs the API server instead; see [Self-hosting](/advanced/self-hosting#docker).

```bash
# Run Math, Logic, SQL and Code on known cases (no LLM needed)
qwed test
# Math:
#   [ok] 2+2=4                  -> VERIFIED | ADMIT
#   [ok] 2+2=5                  -> VERIFIED (false) | DENY
#   ...
```

To prove a claim from its conditions with Z3, see [Logic verification](/getting-started/quickstart#3-logic-verification) in the quick start: given x > 5, the claim x > 3 follows, and x > 10 comes back with a counterexample such as x = 6.

## What's new in v10

<AccordionGroup>
  <Accordion title="Evidence is not proof" icon="shield-check" defaultOpen>
    From v10.0.0, a route reports `VERIFIED`, or admits a result, only on evidence that proves the claim. `/verify/rag`, `/verify/process` and the GitHub Action's `verify-process` mode are `UNVERIFIABLE`. `/verify/consensus` is `BLOCKED` unless two distinct engines verify the same answer. `/verify/logic` carries an admission, and it is `BLOCKED`, because nothing checks that the constraints a model translated mean the question. `/verify/image` decides a size claim only when the claim states the size, and `/verify/math` without `=` is `UNVERIFIABLE`. [Read the 10.0.0 notes →](/changelog#v10-0-0-evidence-is-not-proof)
  </Accordion>
  <Accordion title="Before you upgrade" icon="triangle-exclamation">
    From v10.0.0, `ACTIVE_PROVIDER=claude_opus` is refused: set `ACTIVE_PROVIDER=anthropic` and move its settings to the `ANTHROPIC_` ones. A client that acted on `status == "VERIFIED"` from the routes above now sees `UNVERIFIABLE` or `BLOCKED`, the LangChain and CrewAI tools word undecided results differently, and the Go module path moves to `/v10`. [Read the upgrade steps →](/changelog#v10-0-0-evidence-is-not-proof)
  </Accordion>
</AccordionGroup>
