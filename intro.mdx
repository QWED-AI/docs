## What is QWED?

QWED (Query With Evidence & Determinism) is a trust boundary for AI systems:

- LLMs can translate user intent into structured claims.
- QWED verifies those claims with deterministic engines before execution or response.
- You get proof-backed outcomes instead of probability-only confidence.

QWED is designed for LLM verification, AI agent security, verified tool calls, prompt injection defense, and deterministic transaction verification in high-stakes workflows.

> **"Do not trust generated output. Verify it."**


## Quick start (5 minutes)

```bash
pip install qwed==11.0.0
```

The examples below use the `qwed` CLI that this installs. The `qwedai/qwed-verification:11.0.0` Docker image runs the API server instead; see [Self-hosting](/advanced/self-hosting#docker).

```bash
# Run Math, Logic, SQL and Code on known cases (no LLM needed)
qwed test
# Math:
#   [ok] 2+2=4                  -> VERIFIED | ADMIT
#   [ok] 2+2=5                  -> VERIFIED (false) | DENY
#   ...
```

To prove a claim from its conditions with Z3, see [Logic verification](/getting-started/quickstart#3-logic-verification) in the quick start: given x > 5, the claim x > 3 follows, and x > 10 comes back with a counterexample such as x = 6.

## What's new in v11

<AccordionGroup>
  <Accordion title="Admission only on proof" icon="shield-check" defaultOpen>
    From v11.0.0, the code, SQL, maths, image and guard checks admit only what they can show safe, which fixes ten advisories. `/verify/code` never admits JavaScript, TypeScript, Java or Go, and `/verify/sql` admits only reads of tables and known functions. `/verify/logic` is `VERIFIED` only when the claim follows for every value, and a claim that does not follow comes back with a counterexample. Every translation is screened for prompt injection in one place, before any provider is called. [Read the 11.0.0 notes →](/changelog#v11-0-0-ten-advisories-and-admission-only-on-proof)
  </Accordion>
  <Accordion title="Before you upgrade" icon="triangle-exclamation">
    From v11.0.0, `QWEDLocal.verify`, `verify_math` and `verify_logic` return `verified` False for every claim, and `qwed verify` exits 1: send a maths claim as an equation to `/verify/math`. A satisfiable set of constraints is no longer `VERIFIED` on `/verify/logic`, some SQL and maths that 10.0.0 admitted is now refused, and the Go module path moves to `/v11`. [Read the upgrade steps →](/changelog#v11-0-0-ten-advisories-and-admission-only-on-proof)
  </Accordion>
</AccordionGroup>
