Quick reference for the QWED-Logic Domain Specific Language.

## Overview

QWED-Logic is an S-expression based DSL for expressing logical constraints. It's verified by the Z3 SMT solver for mathematical correctness.

```lisp
(AND (GT x 5) (LT y 10))
```

> **Why S-expressions?** They're unambiguous, easy to parse, and map directly to Z3 constraints.

---

## Basic syntax

```
(OPERATOR arg1 arg2 ...)
```

All expressions are enclosed in parentheses. The operator comes first, followed by arguments.

---

## Logical operators

| Operator | Meaning | Example |
|----------|---------|---------|
| `AND` | Logical AND | `(AND a b c)` |
| `OR` | Logical OR | `(OR a b)` |
| `NOT` | Logical NOT | `(NOT a)` |
| `IMPLIES` | Implication (a → b) | `(IMPLIES a b)` |
| `IFF` | Biconditional (a ↔ b). Both operands must be Boolean. | `(IFF (GT x 1) (GTE x 2))` |
| `XOR` | Exclusive OR | `(XOR a b)` |

### Examples

```lisp
# Both conditions must be true
(AND (GT x 0) (LT x 100))

# At least one must be true
(OR (EQ status "active") (EQ status "pending"))

# If raining, then umbrella (raining and has_umbrella declared Bool)
(IMPLIES raining has_umbrella)

# x > 1 exactly when x >= 2
(IFF (GT x 1) (GTE x 2))
```

`IFF` is a biconditional, not equality. Its operands must be comparisons, `Bool` variables, or `True`/`False`. `(IFF x y)` on two `Int` variables is a compile error, not `x == y`.

---

## Comparison operators

| Operator | Meaning | Example |
|----------|---------|---------|
| `EQ` | Equal (=) | `(EQ x 5)` |
| `NEQ` | Not equal (≠) | `(NEQ x 0)` |
| `GT` | Greater than | `(GT x 5)` |
| `LT` | Less than | `(LT x 10)` |
| `GTE` | Greater or equal (≥) | `(GTE x 0)` |
| `LTE` | Less or equal (≤) | `(LTE x 100)` |

Only these names are on the operator whitelist. `NE`, `GE`, `LE`, and `MUL` return `BLOCKED` with `Unknown operator`.

### Examples

```lisp
# x is between 0 and 100 (exclusive)
(AND (GT x 0) (LT x 100))

# x equals y
(EQ x y)

# Price is at least $10
(GTE price 10)
```

## Arithmetic operators

| Operator | Meaning | Example |
|----------|---------|---------|
| `PLUS` | Addition (+) | `(PLUS x y)` |
| `MINUS` | Subtraction (-) | `(MINUS x y)` |
| `MULT` | Multiplication (*) | `(MULT x y)` |
| `DIV` | Division (/) | `(DIV x y)` |
| `MOD` | Modulo (%) | `(MOD x 2)` |
| `POW` | Power (^) | `(POW x 2)` |
| `ABS` | Absolute value | `(ABS x)` |

### Examples

```lisp
# Check if x + y = 10
(EQ (PLUS x y) 10)

# x squared equals 16
(EQ (POW x 2) 16)

# Even number check
(EQ (MOD x 2) 0)
```

## Quantifiers

| Operator | Meaning | Example |
|----------|---------|---------|
| `FORALL` | For all (∀) | `(FORALL x (GTE (MULT x x) 0))` |
| `EXISTS` | There exists (∃) | `(EXISTS x (EQ x 5))` |

A quantifier takes a binder and a body: `(FORALL x body)` or `(EXISTS x body)`.

- The binder is one plain variable name. The parser returns `BLOCKED` for any other binder, including a list such as `(x)` or `(x y)`, a number, an operator name, or `True`/`False`.
- The bound variable takes its declared sort, or `Int` if it isn't declared.
- The binding applies inside the body only. A free variable with the same name outside the quantifier is unaffected.
- The body must be Boolean. `(FORALL x (PLUS x 1))` is a compile error.
- If Z3 returns `unknown` on a hard quantified formula, the result is `UNKNOWN`. It is never reported as verified.

### Examples

```lisp
# Every square is non-negative
(FORALL x (GTE (MULT x x) 0))

# Every number greater than 5 is greater than 3
(FORALL n (IMPLIES (GT n 5) (GT n 3)))

# Nest quantifiers to bind more than one variable
(EXISTS x (EXISTS y (AND (EQ (PLUS x y) 10) (GT x 0) (GT y 0))))
```

## Special types

### Boolean literals

```lisp
True
False
```

### Variable sorts

Variables are `Int`, `Real`, or `Bool`. An undeclared variable is an `Int`. Declare another sort with `VAR`:

```lisp
(VAR flag Bool)
```

The compiler checks operand sorts and never coerces a Boolean to `1` or `0`:

- `EQ`/`NEQ` between a Boolean (a literal, `Bool` variable, or comparison) and a non-Boolean value is a compile error.
- `GT`, `LT`, `GTE`, and `LTE` reject Boolean operands, because Booleans have no ordering.
- `PLUS`, `MINUS`, `MULT`, `DIV`, `POW`, and `MOD` reject Boolean operands.
- An undeclared name compared with `True` or `False` is a compile error. Declare it with `(VAR name Bool)`.

```lisp
# ERROR: flag is undeclared, so it is an Int
(EQ flag True)

# Valid once flag is declared Bool
(EQ flag True)

# Valid: compares two Booleans
(EQ (GT x 5) True)

# ERROR: Boolean inside arithmetic
(EQ x (PLUS True 0))
```

A compile error returns `ERROR`, never `SAT` or `VERIFIED`.

### Integer constraints

```lisp
(INT x)          # x is an integer
(NAT x)          # x is a natural number (≥ 0)
(POS x)          ; x is positive
```

### Array/list operations

```lisp
(LEN arr)              # Length of array
(GET arr i)            # Get element at index i
(SET arr i val)        # Set element at index i
(SUM arr)              # Sum of all elements
```

## Complete examples

### Example 1: age validation

```lisp
# User must be 18-65 years old
(AND 
  (GTE age 18) 
  (LTE age 65)
)
```

**Python:**
```python
result = client.verify_logic("(AND (GTE age 18) (LTE age 65))")
# SAT with model: {age: 30}
```

### Example 2: budget constraint

```lisp
# Total spending must not exceed budget
(LTE 
  (PLUS food transport entertainment) 
  budget
)
```

### Example 3: password rules

```lisp
# Password must be 8-20 chars with at least 1 uppercase
(AND
  (GTE (LEN password) 8)
  (LTE (LEN password) 20)
  (GT uppercase_count 0)
)
```

### Example 4: scheduling constraint

```lisp
# Meetings can't overlap
(OR
  (LTE meeting1_end meeting2_start)
  (LTE meeting2_end meeting1_start)
)
```

### Example 5: quadratic equation

```lisp
# x² - 5x + 6 = 0 has solutions
(EXISTS x
  (EQ (PLUS (POW x 2) (MULT -5 x) 6) 0)
)
```

## Verification results

| Status | Meaning | Model |
|--------|---------|-------|
| `SAT` | Satisfiable — solution exists | `{x: 6, y: 4}` |
| `UNSAT` | Unsatisfiable — no solution | `null` |
| `UNKNOWN` | Solver timeout or undecidable | `null` |

### Reading results

```python
result = client.verify_logic("(AND (GT x 5) (LT x 10))")

print(result.status)   # "SAT"
print(result.model)    # {"x": 6}
print(result.verified) # True
```

## API usage

### Python

```python
from qwed import QWEDClient

client = QWEDClient(api_key="qwed_your_key")

# Simple constraint
result = client.verify_logic("(GT x 5)")

# Complex constraint
result = client.verify_logic("""
  (AND 
    (GTE x 0) 
    (LTE x 100)
    (EQ (MOD x 7) 0)
  )
""")

if result.status == "SAT":
    print(f"Solution: x = {result.model['x']}")
```

### CLI

```bash
# Verify a constraint
qwed verify-logic "(AND (GT x 5) (LT x 10))"

# From file
echo "(EQ (PLUS x y) 10)" > constraint.dsl
qwed verify-logic -f constraint.dsl
```

### HTTP API

```bash
curl -X POST https://api.qwedai.com/v1/verify/logic \
  -H "Authorization: Bearer qwed_your_key" \
  -H "Content-Type: application/json" \
  -d '{
    "expression": "(AND (GT x 5) (LT y 10))",
    "format": "dsl"
  }'
```

## Common patterns

### Range check
```lisp
(AND (GTE x min) (LTE x max))
```

### Non-empty string
```lisp
(GT (LEN str) 0)
```

### Mutual exclusion
```lisp
(NOT (AND a b))     # a and b can't both be true
```

### At most one
```lisp
(LTE (PLUS (IF a 1 0) (IF b 1 0) (IF c 1 0)) 1)
```

### Exactly one
```lisp
(EQ (PLUS (IF a 1 0) (IF b 1 0) (IF c 1 0)) 1)
```

## Error handling

| Error | Cause | Fix |
|-------|-------|-----|
| `PARSE_ERROR` | Invalid syntax | Check parentheses matching |
| `UNKNOWN_OPERATOR` | Typo in operator | Use valid operator names |
| `TYPE_ERROR` | Boolean and numeric operands mixed, or a non-Boolean `IFF` operand or quantifier body | Declare Boolean variables with `(VAR name Bool)` and keep comparisons and arithmetic numeric |
| `TIMEOUT` | Constraint too complex | Simplify or set longer timeout |

## Grammar (EBNF)

```ebnf
expression     = atom | compound
compound       = "(" operator expression* ")" | quantified
atom           = variable | number | boolean | string
operator       = "AND" | "OR" | "NOT" | "IMPLIES" | "IFF" | "XOR"
               | "EQ" | "NEQ" | "GT" | "LT" | "GTE" | "LTE"
               | "PLUS" | "MINUS" | "MULT" | "DIV" | "MOD" | "POW"
               | "VAR"
quantified     = "(" ( "FORALL" | "EXISTS" ) variable expression ")"
variable       = [a-zA-Z_][a-zA-Z0-9_]*
number         = [-]?[0-9]+("."[0-9]+)?
boolean        = "True" | "False"
string         = "\"" [^\"]* "\""
```
