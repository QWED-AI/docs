**Historical record, not current figures.** These numbers were measured on QWED v1.1.0 in December 2025. The engines, their checks and the fail-closed behaviour have changed a great deal since then, so latency on the current release will differ. Measure on your own workload and hardware before relying on any figure. QWED's current evaluation results are at [qwedai.tech/evidence](https://qwedai.tech/evidence).

Cost comparisons, hosted pricing, an ROI calculator and comparisons with other tools previously on this page were removed: none of them had a reproducible source.
</Warning>

- QWED: v1.1.0

| **Math** | Financial (compound interest) | 8ms | 15ms | 25ms |

### Observations at the time

- Most single-engine checks finished in under 100ms on this hardware.
- ⚠️ **Symbolic execution was slow**: use it only for simple functions.
- ⚠️ **Consensus was expensive**: it makes several LLM API calls.

## Latency optimization tips

### 1. Enable Redis caching

```python
from qwed_sdk import QWEDClient

client = QWEDClient(
    cache_enabled=True,
    redis_url="redis://localhost:6379"
)

# Repeated verifications are served from the cache
```

### 2. Async verification

```python
import asyncio

async def verify_batch(items):
    tasks = [client.verify_async(item) for item in items]
    return await asyncio.gather(*tasks)

# Runs independent verifications concurrently
```

### 3. Selective engines

```python
# Only enable engines you need
client = QWEDClient(engines=["math", "code"])  # Faster startup
```

### 4. Timeout tuning

```python
# Reduce timeout for simple operations
result = engine.verify_math(expr, timeout_ms=1000)  # 1s max
```
