## Quick start

```bash
# Clone the repository
git clone https://github.com/QWED-AI/qwed-verification.git
cd qwed-verification

# Start with Docker Compose
docker-compose up -d

# Check status
docker-compose ps
```

## Configuration

### Environment variables

```bash
# .env file

# Required — server will not start without these
API_KEY_SECRET=your-generated-secret
QWED_CORS_ORIGINS=https://app.yourcompany.com
QWED_AUDIT_SECRET_KEY=your-generated-audit-key  # signs the audit hash chain

# Infrastructure
DATABASE_URL=postgresql://user:pass@localhost:5432/qwed
REDIS_URL=redis://localhost:6379

# LLM provider
ACTIVE_PROVIDER=openai
OPENAI_API_KEY=sk-...

# Required — server will not start without these
API_KEY_SECRET=your-generated-secret  # python -c "import secrets; print(secrets.token_urlsafe(48))"
QWED_CORS_ORIGINS=https://app.yourcompany.com
```

<Warning>
`API_KEY_SECRET` and `QWED_CORS_ORIGINS` are mandatory as of v5.0.0. `QWED_AUDIT_SECRET_KEY` is also mandatory: the server refuses to start without it. See the [deployment guide](/advanced/deployment#environment-variables-reference) for the full reference.
</Warning>

## Docker

### API only

```dockerfile
FROM python:3.13-slim-bookworm
WORKDIR /app
COPY . .
RUN pip install -e .
EXPOSE 8000
CMD ["uvicorn", "qwed_new.api.main:app", "--host", "0.0.0.0"]
```

### Build and run

```bash
docker build -t qwed-api .
docker run -p 8000:8000 \
  -e QWED_API_KEY=... \
  -e API_KEY_SECRET=... \
  -e QWED_AUDIT_SECRET_KEY=... \
  -e QWED_CORS_ORIGINS="https://app.yourcompany.com" \
  qwed-api
```

### Performance tuning

```bash
# Enable connection pooling
export QWED_DB_POOL_SIZE=20
```

<Warning>
Run one uvicorn worker per database. Multiple workers or replicas writing audit rows to the same database are not supported. Every verification request appends an audit row, and the audit logger keeps each organization's chain head in memory. With `--workers 4` or several replicas, a conflicting append makes the verification request fail with `500 audit persistence failed` instead of forking the chain. See [Chain continuity across restarts](/advanced/compliance#chain-continuity-across-restarts).
</Warning>

### Availability limits

QWED bounds request size, slow work, and sandbox usage so one request can't stall or exhaust a server process. The defaults suit most deployments. Raise them only if your host has the headroom.

| Variable | Default | What it bounds |
|----------|---------|----------------|
| `QWED_CODE_VERIFY_TIMEOUT` | `10` | Seconds a `/verify/code` scan can run. A timeout returns `503`. |
| `QWED_PROVIDER_TIMEOUT` | `30` | Seconds an LLM provider call can run for `/verify/natural_language`, `/verify/logic`, and `/verify/fact`. Calls run off the event loop. A timeout fails closed: `/verify/fact` returns `503`, the others return an `ERROR` result. |
| `QWED_Z3_TIMEOUT` | `15` | Seconds a `/verify/logic` Z3 solve can run. Solves run one at a time on a dedicated thread. |
| `QWED_BATCH_MAX_JOBS` | `1000` | Jobs kept in the `/verify/batch` job store. QWED evicts the oldest finished job first and never evicts a running job. An evicted job returns `404` from `GET /verify/batch/{job_id}`. When every stored job is active, new submissions get `503 Batch capacity reached — retry shortly.` |
| `QWED_BATCH_ITEM_TIMEOUT` | `60` | Seconds a single batch item can run. A timed-out item is marked `failed` so the job can finish. |
| `QWED_SANDBOX_MAX_CONCURRENT` | `4` | Sandbox containers running at once per server process, across `/verify/consensus` and `/verify/stats` with the Docker executor. |
| `QWED_SANDBOX_ACQUIRE_TIMEOUT` | `10` | Seconds a request waits for a free sandbox slot. If none frees in time, QWED rejects the run with `Sandbox capacity reached — retry shortly.` instead of starting another container. |

```bash
# Example: a larger host that runs more sandboxed verifications in parallel
export QWED_SANDBOX_MAX_CONCURRENT=8
export QWED_PROVIDER_TIMEOUT=45
```

Request body caps are fixed. Every `/verify` JSON route accepts up to 1,000,000 bytes. `/verify/stats` and `/verify/image` accept their 10 MB file limit plus envelope headroom. QWED rejects an oversized body with `413` before processing it. See [Request limits](/api/endpoints#request-limits) for the full error list.

<Note>
`QWED_SANDBOX_MAX_CONCURRENT` applies per worker process. With `uvicorn --workers 4` and the default of 4, a host can run up to 16 sandbox containers. Size the value against your host's memory, CPU, and PID limits.
</Note>

### Sandbox image and container user

<Info>v8.0.0</Info>

`/verify/stats` and `/verify/consensus` run model-generated Python in a Docker sandbox. QWED pins the sandbox image by digest, so the sandbox only ever runs the exact image that was reviewed:

```text
amancevice/pandas@sha256:9257b88909bddf60c8a85b06d572fc6dfc708ea9c8a3c3dc2149e312d57f91e3
```

Each sandbox container runs with a read-only root filesystem, drops all Linux capabilities, sets `no-new-privileges`, and never runs as a privileged root. The only writable path is the per-execution `/workspace` directory, which is a private `0700` host directory. The container runs as that directory's owner:

- **Non-root server process:** the container runs as the host user.
- **Root server process:** QWED hands each workspace to a fresh uid for that execution. QWED skips any uid that a host account or group owns, that `/etc/subuid` or `/etc/subgid` delegates, or that another running execution uses.
- **Rootless daemon run by the same non-root user:** the container runs as its root, which the daemon maps to that unprivileged host user.

| Variable | Default | Purpose |
|----------|---------|---------|
| `QWED_SANDBOX_IMAGE` | Pinned image above | Runs a different sandbox image, such as a mirror in your own registry. The value must be pinned by digest (`name@sha256:<64 hex>`). QWED refuses any other value, logs an error, and uses the pinned image. |
| `QWED_SANDBOX_UID_RANGE` | `1879048192-2147483646` | The uid range QWED draws workspace owners from when the server process runs as root. Use `FIRST-LAST` within `65536`–`2147483646`. QWED logs an invalid value and uses the default. The default is a range systemd documents as unused. |

```bash
# Mirror the sandbox image in a private registry, pinned by digest
export QWED_SANDBOX_IMAGE=registry.example.com/qwed/pandas@sha256:9257b88909bddf60c8a85b06d572fc6dfc708ea9c8a3c3dc2149e312d57f91e3

# Reserve a dedicated uid range for root-run deployments
export QWED_SANDBOX_UID_RANGE=2000000000-2000099999
```

<Warning>
QWED never guesses how the Docker daemon maps users. It reports the sandbox as unavailable (`SECURE_RUNTIME_UNAVAILABLE`) when any of the following is true. `/verify/stats` then returns `BLOCKED` with constraint `stats_verifier.runtime_unavailable`, and `/verify/consensus` counts its code-execution engine as `BLOCKED`.

- the daemon uses `userns-remap`
- the server process runs as root with a rootless daemon
- QWED can't read the daemon's security options
</Warning>

## Monitoring

### Health check

```bash
curl http://localhost:8000/health
```

### Prometheus metrics

```text
qwed_verification_total{engine="math", status="verified"}
qwed_verification_latency_seconds
qwed_cache_hit_rate
```

Scrape `GET /metrics/prometheus` (the Prometheus text exposition format — `/metrics` returns JSON). The endpoint requires a platform operator: create a dedicated scraper account, add its user ID to `QWED_METRICS_OPERATOR_USER_IDS` (fail-closed when unset — every caller is denied, including org owners/admins), mint the account an API key, and send it as a header on the scrape. See [All-tenant metrics authorization](/advanced/security-hardening#all-tenant-metrics-authorization).

```yaml
# prometheus scrape config
scrape_configs:
  - job_name: 'qwed-api'
    metrics_path: '/metrics/prometheus'
    static_configs:
      - targets: ['localhost:8000']
    http_headers:
      X-Api-Key:
        values: ['qwed_live_********************************wDHo']  # masked v2 example (see API key format) — render the real one from your secret pipeline
```

## Security

1. **Always use HTTPS** in production
2. **Set `API_KEY_SECRET`** — mandatory, no default value
3. **Set `QWED_CORS_ORIGINS`** — mandatory, explicitly list allowed origins
4. **Set strong API keys**
5. **Enable rate limiting**
6. **Use network isolation**
7. **Rotate secrets regularly**
8. **Configure `QWED_METRICS_OPERATOR_USER_IDS`** if anything needs all-tenant metrics — unset means deny-all
