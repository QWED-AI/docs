## Quick start

### Prerequisites

- Docker with the Compose plugin (`docker compose`)
- A clone of the `qwed-verification` repository

```bash
# Clone the repository
git clone https://github.com/QWED-AI/qwed-verification.git
cd qwed-verification

# Copy the settings template, then fill in every required value
cp deploy/.env.example deploy/.env

# Build the server image and start the stack from the repository root
docker compose -f deploy/docker-compose.yml up -d

# Check status
docker compose -f deploy/docker-compose.yml ps
```

Compose builds the API server from the repository's `Dockerfile` (the `server` target) and waits for Postgres, Redis, and Jaeger to report healthy before it starts the API.

<Warning>
Compose refuses to start while `QWED_CORS_ORIGINS`, `API_KEY_SECRET`, `QWED_JWT_SECRET_KEY`, `QWED_API_KEY_LOOKUP_SECRET`, `QWED_AUDIT_SECRET_KEY`, or `DATABASE_URL` is empty. The Postgres container refuses to start while `POSTGRES_PASSWORD` is empty, and the Grafana container refuses to start while `GF_SECURITY_ADMIN_PASSWORD` is empty.
</Warning>

## Services

| Service | Port | Purpose |
| --- | --- | --- |
| QWED API (`qwed-core`) | 8000 | Main API |
| PostgreSQL | 5432 | Database |
| Redis | 6379 | Cache & rate limiting |
| Grafana | 3000 | Dashboards, with Prometheus and Jaeger data sources provisioned |
| Prometheus | 9090 | Metrics. Scrapes the API at `qwed-core:8000` |
| Jaeger | 16686 | Tracing |

The API server keeps its data in the `qwed-data` volume. Postgres, Redis, Prometheus, and Grafana each have their own named volume, so data survives `docker compose down`.

## Configuration

### Environment variables

`deploy/.env.example` lists every setting the Compose stack reads. Generate each secret separately:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

```bash
# deploy/.env

# QWED API server (required)
QWED_CORS_ORIGINS=https://app.yourcompany.com
API_KEY_SECRET=your-generated-secret
# Keep the next three stable. Changing them invalidates issued tokens and
# API keys, or breaks the signed audit chain. The lookup secret must differ
# from the JWT secret.
QWED_JWT_SECRET_KEY=your-generated-secret
QWED_API_KEY_LOOKUP_SECRET=another-generated-secret
QWED_AUDIT_SECRET_KEY=another-generated-secret

# Optional. User IDs allowed to read /metrics. Empty denies every caller.
QWED_METRICS_OPERATOR_USER_IDS=

# Postgres (required)
POSTGRES_USER=qwed
POSTGRES_DB=qwed_db
POSTGRES_PASSWORD=
# Must match the three values above. Build it as a postgresql:// URL with the
# user, POSTGRES_PASSWORD, the host "postgres" (the Compose service), port 5432
# and qwed_db, the same shape as deploy/.env.example shows.
DATABASE_URL=

# Grafana (required)
GF_SECURITY_ADMIN_USER=admin
GF_SECURITY_ADMIN_PASSWORD=your-grafana-password
```

Postgres and Grafana receive only their own settings, not the API server's secrets. `deploy/.env` is git-ignored.

<Warning>
`QWED_METRICS_OPERATOR_USER_IDS` is optional. Leave it empty and every caller, including the Prometheus scraper, gets denied on `/metrics`. Prometheus records `401` responses until you configure an operator. See [Prometheus metrics](#prometheus-metrics). See the [deployment guide](/advanced/deployment#environment-variables-reference) for the full variable reference.
</Warning>

## Docker

### API server image

The `qwedai/qwed-verification` image on Docker Hub runs the API server with uvicorn on port 8000. Docker Hub publishes `latest` from `main` and a versioned tag for each release from 8.0.0.

The image:

- Runs as a non-root user (UID 1000).
- Uses `/var/lib/qwed` as its working directory. The default SQLite database (`sqlite:///./qwed.db`) lives there. Mount a volume at `/var/lib/qwed` to keep it, or set `DATABASE_URL` to use Postgres.
- Has a health check that calls `GET /health` with the image's own Python.
- Reads its bind address and port from `UVICORN_HOST` (default `0.0.0.0`) and `UVICORN_PORT` (default `8000`). The health check follows `UVICORN_PORT`, so change the port with `-e UVICORN_PORT=...` rather than a `--port` argument.

<Warning>
Tags before 8.0.0 ran the QWED GitHub Action, not the API server. If you ran the image as a repository scanner, use the [GitHub Action](/advanced/github-action) instead.
</Warning>

### Run the published image

Pass the secrets from your shell, so no value is written into the command:

```bash
# Generate each secret once and keep it. Changing the lookup or audit key later
# invalidates existing API keys or audit signatures.
for name in API_KEY_SECRET QWED_JWT_SECRET_KEY QWED_API_KEY_LOOKUP_SECRET QWED_AUDIT_SECRET_KEY; do
  export "$name=$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
done

docker run -d -p 8000:8000 \
  -v qwed-data:/var/lib/qwed \
  -e QWED_CORS_ORIGINS="https://app.yourcompany.com" \
  -e API_KEY_SECRET \
  -e QWED_JWT_SECRET_KEY \
  -e QWED_API_KEY_LOOKUP_SECRET \
  -e QWED_AUDIT_SECRET_KEY \
  qwedai/qwed-verification:8.0.0
```

The server refuses to start without any of `QWED_CORS_ORIGINS`, `API_KEY_SECRET`, `QWED_JWT_SECRET_KEY`, `QWED_API_KEY_LOOKUP_SECRET` and `QWED_AUDIT_SECRET_KEY`, and `QWED_API_KEY_LOOKUP_SECRET` must differ from `QWED_JWT_SECRET_KEY`. Also set `QWED_SIGNING_KEY` (an EC P-256 key), or attestations stop verifying after a restart or on another replica.

To serve on a different port, with the same secrets exported:

```bash
docker run -d -p 9000:9000 -e UVICORN_PORT=9000 \
  -e QWED_CORS_ORIGINS="https://app.yourcompany.com" \
  -e API_KEY_SECRET \
  -e QWED_JWT_SECRET_KEY \
  -e QWED_API_KEY_LOOKUP_SECRET \
  -e QWED_AUDIT_SECRET_KEY \
  qwedai/qwed-verification:8.0.0
```

### Build from source

The repository's `Dockerfile` has two targets. `server` is the API server. `action` is the GitHub Action and stays the default target, so build the server with `--target server`:

```bash
docker build --target server -t qwed-api .
```

## Kubernetes

The repository ships manifests in `deploy/kubernetes/`. The Deployment pins `docker.io/qwedai/qwed-verification:8.0.0`, the first tag that contains the API server. Fill in every value in `deploy/kubernetes/secret.yaml` before you apply it. See [Kubernetes deployment](/advanced/deployment#kubernetes-deployment).

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: qwed-core
  namespace: qwed
spec:
  replicas: 1
  selector:
    matchLabels:
      app: qwed-core
  template:
    metadata:
      labels:
        app: qwed-core
    spec:
      containers:
      - name: qwed-core
        image: docker.io/qwedai/qwed-verification:8.0.0
        ports:
        - containerPort: 8000
        envFrom:
        - configMapRef:
            name: qwed-config
        - secretRef:
            name: qwed-secrets
```

### Availability limits

QWED bounds request size, slow work, and sandbox usage so one request can't stall or exhaust a server process. The defaults suit most deployments. Raise them only if your host has the headroom.

| Variable | Default | What it bounds |
|----------|---------|----------------|
| `QWED_CODE_VERIFY_TIMEOUT` | `10` | Seconds a `/verify/code` scan can run. A timeout returns `503`. |
| `QWED_PROVIDER_TIMEOUT` | `30` | Seconds an LLM provider call can run for `/verify/natural_language`, `/verify/logic`, and `/verify/fact`. Calls run off the event loop. A timeout fails closed: `/verify/fact` returns `503`, the others return an `ERROR` result. |
| `QWED_Z3_TIMEOUT` | `15` | Seconds a `/verify/logic` Z3 solve can run. Solves run one at a time on a dedicated thread. |
| `QWED_BATCH_MAX_JOBS` | `1000` | Jobs kept in the `/verify/batch` job store. QWED evicts the oldest finished job first and never evicts a running job. An evicted job returns `404` from `GET /verify/batch/{job_id}`. When every stored job is active, new submissions get `503 Batch capacity reached — retry shortly.` |
| `QWED_BATCH_ITEM_TIMEOUT` | `60` | Seconds a single batch item can run. A timed-out item is marked `failed` so the job can finish. |
| `QWED_SANDBOX_MAX_CONCURRENT` | `4` | Sandbox containers running at once per server process, across `/verify/consensus` and `/verify/stats` with the Docker executor. |
| `QWED_SANDBOX_ACQUIRE_TIMEOUT` | `10` | Seconds a request waits for a free sandbox slot. If none frees in time, QWED rejects the run with `Sandbox capacity reached — retry shortly.` instead of starting another container. |

```bash
# Example: a larger host that runs more sandboxed verifications in parallel
export QWED_SANDBOX_MAX_CONCURRENT=8
export QWED_PROVIDER_TIMEOUT=45
```

Request body caps are fixed. Every `/verify` JSON route accepts up to 1,000,000 bytes. `/verify/stats` and `/verify/image` accept their 10 MB file limit plus envelope headroom. QWED rejects an oversized body with `413` before processing it. See [Request limits](/api/endpoints#request-limits) for the full error list.

<Note>
`QWED_SANDBOX_MAX_CONCURRENT` applies per worker process. With `uvicorn --workers 4` and the default of 4, a host can run up to 16 sandbox containers. Size the value against your host's memory, CPU, and PID limits.
</Note>

## Monitoring

### Health check

```bash
curl http://localhost:8000/health
```

### Prometheus metrics

```text
qwed_verification_total{engine="math", status="verified"}
qwed_verification_latency_seconds
qwed_cache_hit_rate
```

Scrape `GET /metrics/prometheus` (the Prometheus text exposition format — `/metrics` returns JSON). The endpoint requires a platform operator: create a dedicated scraper account, add its user ID to `QWED_METRICS_OPERATOR_USER_IDS` (fail-closed when unset — every caller is denied, including org owners/admins), mint the account an API key, and send it as a header on the scrape. See [All-tenant metrics authorization](/advanced/security-hardening#all-tenant-metrics-authorization).

```yaml
# prometheus scrape config
scrape_configs:
  - job_name: 'qwed-api'
    metrics_path: '/metrics/prometheus'
    static_configs:
      - targets: ['localhost:8000']
    http_headers:
      X-Api-Key:
        values: ['qwed_live_********************************wDHo']  # masked v2 example (see API key format) — render the real one from your secret pipeline
```

## Security

1. **Always use HTTPS** in production
2. **Set `API_KEY_SECRET`** — mandatory, no default value
3. **Set `QWED_CORS_ORIGINS`** — mandatory, explicitly list allowed origins
4. **Set strong API keys**
5. **Enable rate limiting**
6. **Use network isolation**
7. **Rotate secrets regularly**
8. **Configure `QWED_METRICS_OPERATOR_USER_IDS`** if anything needs all-tenant metrics — unset means deny-all
