## Installation

```bash
pip install qwed langchain
```

## Quick start

```python
from qwed_sdk.langchain import QWEDTool, QWEDVerificationCallback

# Add QWED as a tool
from langchain.agents import initialize_agent, AgentType
from langchain.llms import OpenAI

agent = initialize_agent(
    tools=[QWEDTool()],
    llm=OpenAI(),
    agent=AgentType.ZERO_SHOT_REACT_DESCRIPTION,
)

result = agent.run("Verify: Is 2+2 equal to 5?")
# Agent uses QWED tool to verify and corrects the answer
```

## Available components

### QWEDTool

General-purpose verification tool:

```python
from qwed_sdk.langchain import QWEDTool

tool = QWEDTool(api_key="qwed_...")
print(tool.run("2+2=4"))
# ⚠️ HOLDS, NOT ADMITTED: the claim holds for the translated expression <expression>, but it was translated from your query by an LLM, and that translation is not verified.
```

`QWEDTool` sends its input to `/verify/natural_language`, which admits no result while the LLM's translation of the query is unverified. So the tool says what holds for the translated expression and that it is not admitted. A claim proven false for that expression starts with `❌ INCORRECT for the translated expression`, and a result QWED did not decide is `⚠️ UNVERIFIABLE:` or `⛔ BLOCKED:` followed by the server's message.

### Specialized tools

```python
from qwed_sdk.langchain import QWEDMathTool, QWEDLogicTool, QWEDCodeTool

tools = [
    QWEDMathTool(),   # Math expressions
    QWEDLogicTool(),  # QWED-Logic DSL
    QWEDCodeTool(),   # Code security
]
```

<Info>Changed in v10.0.0</Info>

The tools call a result wrong only when QWED decided it. A result QWED did not decide is reported with its status and the server's message.

| Tool | Result | Answer |
| --- | --- | --- |
| `QWEDMathTool` | Admitted | `✅ VERIFIED: <expression> is correct` |
| `QWEDMathTool` | `VERIFIED`, claim proven false | `❌ INCORRECT:` and the server's message |
| `QWEDLogicTool` | `VERIFIED`, not admitted | `⚠️ SAT, NOT ADMITTED:` with the assignment, and why it is not admitted |
| `QWEDLogicTool` | `UNVERIFIABLE`, unsatisfiable | `❌ UNSAT: no assignment satisfies the translated constraints.` |
| `QWEDCodeTool` | Admitted | `✅ SAFE: No security issues detected` |
| `QWEDCodeTool` | `VERIFIED`, proven unsafe | `⚠️ SECURITY ISSUES:` and up to five `severity: description` lines |
| All three | `UNVERIFIABLE` | `⚠️ UNVERIFIABLE:` and the server's message |
| All three | `BLOCKED` | `⛔ BLOCKED:` and the server's message |

`/verify/logic` admits no result while the LLM's translation of the query is unverified, so `QWEDLogicTool` reports a satisfiable query as `SAT, NOT ADMITTED`, not `SAT`.

### QWEDVerificationCallback

Checks what it recognises in each LLM, chain and agent output: the math it finds, each fenced block (as SQL or as code, by its tag), and SQL outside a block, which it records as `UNVERIFIABLE`. Outside a block, it finds a statement by its keywords in capitals, such as `SELECT ... FROM` or `DELETE FROM`. Only a statement that creates, drops, alters or truncates a table is found in any case. Lowercase SQL such as `delete from users;` is not found, so it is not checked. Anything else, such as a claim in prose, is not checked.

```python
from langchain.chains import LLMChain
from qwed_sdk.langchain import QWEDVerificationCallback

callback = QWEDVerificationCallback(
    verify_math=True,
    verify_code=True,
    sql_schema_ddl="CREATE TABLE users (id INT, name TEXT)",
    sql_dialect="sqlite",
    log_results=True,
)

chain = LLMChain(
    llm=OpenAI(),
    prompt=prompt,
    callbacks=[callback]
)

result = chain.run("Calculate 15% of 200")
# LLM output: "15% of 200 = 30"
# [QWED] ❌ MATH: verified=False
```

The math check sends the output to `/verify/natural_language`, which admits no result while the LLM's translation is unverified, so it logs `verified=False`. `verify_sql` is on by default: a SQL block is checked against `sql_schema_ddl` in `sql_dialect` (default `sqlite`). Without a schema, SQL is recorded as `UNVERIFIABLE` and nothing is sent. `get_summary()` counts an output as verified only when a check ran and every check verified it. SQL the callback did not find is not a check, so an output with an admitted code block and `delete from users;` in its text counts as verified.

### QWEDVerifiedChain

Wrap any chain with verification:

```python
from qwed_sdk.langchain import QWEDVerifiedChain

base_chain = LLMChain(llm=llm, prompt=prompt)
verified_chain = QWEDVerifiedChain(base_chain, auto_correct=True)

result = verified_chain.run("What is 2+2?")
print(result.output)    # "4"
print(result.verified)  # False
```

The callback and `QWEDVerifiedChain` read the client's `is_verified`, which follows the server's admission: `result.verified` is `True` only when the server admitted the output, and a `BLOCKED` or `UNVERIFIABLE` result is never verified. `QWEDVerifiedChain` checks the output with `client.verify()`, which calls `/verify/natural_language`, so `result.verified` is `False` while that route admits no result. The tools call a result wrong only when QWED decided it.

<Warning>
Before v8.0.0 ([GHSA-83v6-6h23-pvp4](https://github.com/QWED-AI/qwed-verification/security/advisories/GHSA-83v6-6h23-pvp4)), the integrations read a `verified` attribute that `QWEDClient` results don't have, so their checks raised. When you call `QWEDClient` directly, gate on `result.is_verified`.
</Warning>

## LCEL integration

Use with LangChain Expression Language:

```python
from langchain_core.runnables import RunnableLambda

def verify_output(text):
    from qwed_sdk import QWEDClient
    client = QWEDClient()
    result = client.verify(text)
    return text if result.is_verified else f"[UNVERIFIED] {text}"

chain = prompt | llm | RunnableLambda(verify_output)
```

## Best practices

1. **Use callbacks for monitoring** — Track verification rates
2. **Use tools for agent autonomy** — Let agents verify themselves
3. **Use wrappers for guarantees** — Ensure all outputs are verified
