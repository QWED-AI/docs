Common issues and solutions when using QWED-MCP.

---

## Installation issues

### "qwed-mcp: command not found"

**Cause:** Package not in PATH

**Solutions:**

1. **Install globally:**
   ```bash
   pip install qwed-mcp
   ```
2. **Check installation:**
   ```bash
   pip show qwed-mcp
   python -m qwed_mcp.server
   ```
3. **Use full path in config:**
   ```json
   {
     "mcpServers": {
       "qwed-verification": {
         "command": "python",
         "args": ["-m", "qwed_mcp.server"]
       }
     }
   }
   ```

## Claude Desktop issues

### Server not appearing in Claude

**Check:**

1. **Config file location:**
   - Windows: `%APPDATA%\Claude\claude_desktop_config.json`
   - macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`
2. **Valid JSON:**
   ```bash
   python -c "import json; json.load(open('path/to/config.json'))"
   ```
3. **Restart Claude Desktop** (completely quit and reopen)

---

### "Failed to start MCP server"

**Debug steps:**

1. **Test manually:**
   ```bash
   qwed-mcp
   # Should start without errors
   # Press Ctrl+C to exit
   ```
2. **Check logs:**
   ```bash
   # Windows
   type %APPDATA%\Claude\logs\mcp*.log
   # macOS
   cat ~/Library/Logs/Claude/mcp*.log
   ```
3. **Enable debug logging:**
   ```json
   {
     "mcpServers": {
       "qwed-verification": {
         "command": "qwed-mcp",
         "env": {
           "QWED_LOG_LEVEL": "DEBUG",
           "QWED_MCP_TRUSTED_CODE_EXECUTION": "true"
         }
       }
     }
   }
   ```

## Tool errors

### "Code execution is disabled"

**Cause:** The `QWED_MCP_TRUSTED_CODE_EXECUTION` environment variable is not set.

**Solution:** Set the variable in your MCP config:

```json
{
  "mcpServers": {
    "qwed-verification": {
      "command": "qwed-mcp",
      "env": {
        "QWED_MCP_TRUSTED_CODE_EXECUTION": "true"
      }
    }
  }
}
```

Or when running from the command line:

```bash
QWED_MCP_TRUSTED_CODE_EXECUTION=true qwed-mcp
```

---

### "BLOCKED: Unknown MCP tool" (or verify\_\* tools)

**Cause:** You are running QWED-MCP v0.2.0 or later, which replaced all individual `verify_*` tools with a single `execute_python_code` tool. The `RiskBasedExecutionGateway` blocks any tool name not in its policy table with error code `QWED-MCP-RISK-001`.

The full error message looks like:

```text
BLOCKED: Unknown MCP tool 'verify_math' is blocked by default. (verification_id=...)
```

**Solution:** Tell Claude: *"The verify\_\* tools have been removed. Use execute\_python\_code to write and run a Python verification script."*

See the [migration guide](/mcp/tools#migrating-from-v0-1-x) and [governance error codes](/mcp/tools#governance-error-codes) for the complete list of `QWED-MCP-RISK-*` codes.

---

### "Execution timed out after 30 seconds"

**Cause:** The Python script exceeded the execution time limit.

**Solutions:**

1. **Increase timeout:**
   ```bash
   QWED_TIMEOUT=60 qwed-mcp
   ```
2. **Optimize the script:**
   - Break complex computations into smaller steps
   - Avoid infinite loops or very large data processing

---

### "BLOCKED: QWED blocked python execution: Module '...' is not admitted"

**Cause:** From v0.3.0, `execute_python_code` admits code only when every module, builtin and attribute it uses is on the allowlist. Third-party packages are refused, including SymPy and QWED SDK packages such as `qwed_new`, `qwed_legal`, `qwed_finance` and `qwed_ucp`. Installing the package doesn't change this. The message lists every reason with its line number, for example:

```text
BLOCKED: QWED blocked python execution: Module 'qwed_legal' is not admitted (line 1) (verification_id=...)
```

**Solutions:**

1. Rewrite the script with [admitted modules](/mcp/tools#what-code-is-admitted), such as `decimal`, `fractions`, `math`, `statistics` or `itertools`.
2. To run a QWED guard or engine, call its package from your own Python code instead of through `execute_python_code`.

## Migration issues (v0.1.x to v0.2.0)

### Claude keeps trying to call verify\_math

**Cause:** Claude's context may still reference old tool names from previous conversations.

**Solutions:**

1. Start a new conversation
2. Explicitly tell Claude: *"Use execute\_python\_code instead of verify\_math. Write a Python script with the decimal or fractions module to check the calculation."*

## Upgrade issues (v0.2.x to v0.3.0)

### Scripts that ran on v0.2.x are refused

**Cause:** v0.3.0 replaced the list of refused names with an allowlist. Code that imports a module outside it (`os`, `pathlib`, `requests`, QWED SDK packages and other third-party packages), calls `open`, `eval`, `getattr` or another refused builtin, or reads a private or special attribute is now refused. A coding declaration other than UTF-8 is refused too.

**Solution:** Read the reasons in the `BLOCKED` message and rewrite the script with [admitted modules and builtins](/mcp/tools#what-code-is-admitted).

### Your code can't import qwed-finance or qwed-ucp

**Cause:** From v0.3.0, installing qwed-mcp no longer installs `qwed-finance` or `qwed-ucp`.

**Solution:** If your own code imports them, install them in your project:

```bash
pip install qwed-finance qwed-ucp
```

### The server refuses to start with a skill manifest

**Cause:** From v0.3.0, when `QWED_SKILL_MANIFEST` is set, the startup check refuses a registry that is not one of the built-in trusted domains (`github.com`, `gitlab.com`, `bitbucket.org`, `pypi.org`, `npmjs.com`).

**Solution:** Use a manifest from a trusted registry, or vet the skill in your own code with [`SkillProvenanceGuard`](/mcp/tools#skillprovenanceguard-security) and that registry in `trusted_registries`.
